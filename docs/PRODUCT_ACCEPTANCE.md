# CCSwitch Pulse 产品与发布验收

## 产品定位

让 CC Switch 用量数据成为可回看、可解释、可分享的个人使用记录。核心路径是：选择时段 → 看模型曲线 → 从任意时刻回放 → 阅读周期报告 → 预览并导出分享图。

界面面向桌面浏览器；报告和图片在本机生成；不需要账号、云端服务或大模型文案生成。

## 功能边界与统计口径

| 能力 | 验收口径 |
| --- | --- |
| 时间范围 | 近 24 小时、近 7 天、近 30 天、本周、本月、今年、全部和自定义；日历周从周一开始。 |
| 统计指标 | 调用量、Token、估算美元费用、模型数；费用来自 CC Switch 记录，不作为账单。 |
| 历史数据 | `proxy_request_logs` 明细与 `usage_daily_rollups` 归档汇总可以合并统计；归档只有日粒度，不能还原小时数据。 |
| 模型口径 | 实际模型读取 `model`；请求模型优先读取 `request_model`，为空时回退。 |
| 对比 | 日历周、月、年按上期相同进度比较；没有完整可比时段时不显示百分比。 |
| 时间回放 | 播放、暂停、逐格、速度、拖动和当前时段排行同步更新。 |
| 报告 | 展示主力模型、模型构成、活跃天数、峰值、周期日均、趋势和数据覆盖说明；日均按所选时间跨度计算。 |
| 分享图 | 浏览器本地生成 16:9 PNG；费用默认隐藏；支持预览、下载和复制。Token 节奏模板以 Token 总量为主指标。 |
| 会话 | 仅聚合有稳定 `session_id` 的导入明细；不暴露 session ID、提示词或响应内容。 |
| 项目归属 | 当前不展示项目级排名，避免把配置 profile 误当成工作项目。 |

## 数据库契约

当前实现依赖以下表和字段：

### 必需表：`proxy_request_logs`

```text
created_at
model
data_source
input_tokens
output_tokens
cache_read_tokens
cache_creation_tokens
total_cost_usd
```

以下字段为可选字段：

```text
request_model
status_code
session_id
```

### 可选表：`usage_daily_rollups`

```text
date
model
request_count
input_tokens
output_tokens
cache_read_tokens
cache_creation_tokens
total_cost_usd
```

`request_model` 在归档表中为可选字段。若数据库不满足表结构，应用必须显示可理解的 schema 错误，而不是静默展示不完整数据。

## 桌面布局与图片回归（v0.1.6）

- 修复 v0.1.5 在云端 macOS/Linux 的 1280px 日期筛选溢出：范围整组按实际字体和可用宽度换行，不再依赖假定的 920px 断点。
- 验收宽度：1920、1600、1440、1320、1280、1240、1180、1094、1024、900px；中英文 × 深浅主题，共 40 个布局组合。
- 日期/时间组合框宽度不超过 160px；日期文字到时间分隔线不超过 34px；起始、结束等宽同一行；应用按钮保留右侧至少 8px 安全边距。
- 额外覆盖 1280px 较宽回退字体和文字宽度压力，不放宽原有横向溢出、边距和对齐断言。
- 两个日历定位在对应输入框下方 8px，窗口改变大小后重新定位；Escape 关闭并恢复焦点，清除日期不改变框宽。
- 分享卡覆盖四个模板 × 双语 × 双主题，验证原始 PNG 为 2400 × 1350px、模型数量完整、页脚图标与文字不重叠。
- README 使用演示服务的 14 张 2× 图片，总览包含完整曲线与图例；内容哈希文件名、版本和源码指纹纳入 CI，避免漏更新。
- 本机测试不能替代云端验收；以同一提交的三系统 GitHub Actions 结果为最终发布依据。
