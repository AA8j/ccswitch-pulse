# CCSwitch Pulse 发布清单

这是面向维护者的发布检查表，不是运行时文档。所有结论都必须基于当前待发布 commit 的实际命令输出、浏览器结果和截图，不以历史记录或宣传图代替验证。

## 发布范围

- 目标平台：桌面浏览器；本项目不承诺移动端布局。
- 运行环境：Node.js 24.6+、npm、桌面浏览器。
- 数据来源：本机 CC Switch SQLite 数据库，或内置演示数据。
- 网络边界：服务只监听 `127.0.0.1`，不上传用量数据。

## Gate 0：代码与依赖

- [ ] 工作树干净，待发布 commit 已记录。
- [ ] `npm ci` 成功。
- [ ] `npm test` 成功。
- [ ] `npm run check:syntax` 成功。
- [ ] `npm run test:coverage` 成功并记录覆盖率。
- [ ] `npm run pack:check` 成功。
- [ ] `npm pack` 内容没有数据库、日志、缓存和本机绝对路径。
- [ ] 依赖审计已执行并记录结果。
- [ ] `npm run smoke:cli` CLI/API 冒烟通过。
- [ ] `npm run test:e2e` 桌面端 E2E 通过。
- [ ] `npm run benchmark -- 100000` 性能基线已记录。

## Gate 1：核心流程

使用演示数据完整执行：

```text
启动 → 选择范围 → 切换来源 → 查看图表
→ 切换指标和图表类型 → 回放 → 展开明细
→ 查看报告 → 下载 Markdown → 生成并下载 PNG
```

- [ ] 24 小时、7 天、30 天、本周、本月、今年、全部、自定义均可用。
- [ ] 来源筛选后再次切换“全部”不会丢失起止时间。
- [ ] Top 5 / 全部模型状态正确。
- [ ] 中英文切换不重置范围、模型选择和回放位置。
- [ ] 深浅主题切换不改变布局。
- [ ] 空范围、空库、缺库和错误数据库均有清晰状态。

## Gate 2：数据口径

- [ ] 近期明细与历史日汇总可独立复算。
- [ ] 归档数据不会被画成小时或分钟明细。
- [ ] 混合数据不会重复计算。
- [ ] 周从周一开始，跨年、跨月和时区边界已验证。
- [ ] 请求模型为空时正确回退到实际模型。
- [ ] 缺少可选字段时仍能读取安全字段。
- [ ] 没有稳定 session_id 时明确提示会话视图不可用。
- [ ] Token、费用、调用量的定义已在 README 和界面中一致说明。

## Gate 3：桌面端视觉与可访问性

- [ ] 1024、1280、1440 和 1920 宽度无横向溢出。
- [ ] 中文和英文没有按钮、卡片、表格或分享图截断。
- [ ] 关键控件可通过键盘访问。
- [ ] 图表、热力图、报告和明细拥有可理解的无障碍名称。
- [ ] reduced-motion 设置生效。
- [ ] 浏览器控制台没有 error。
- [ ] 宣传截图没有焦点框、加载态、弹窗背景或个人数据。

## Gate 4：隐私与安全

- [ ] 数据库只读打开。
- [ ] API 只允许 GET / HEAD。
- [ ] 服务只监听 `127.0.0.1`。
- [ ] API 不返回 prompt、response、session ID、provider 配置或项目路径。
- [ ] 分享 PNG 不包含上述隐私字段。
- [ ] 数据库错误不会泄漏完整本机路径。

## Gate 5：干净环境安装

仓库公开后，使用真实 GitHub owner 执行：

```bash
npx -y "github:aa8j/ccswitch-pulse" --demo --no-open
```

- [ ] 无源码 checkout 的目录可以启动。
- [ ] CLI 能显示本地 URL、数据源和停止方式。
- [ ] `--help`、`--db`、`--port 0`、`--no-open` 均可用。
- [ ] 浏览器能加载静态资源和 ECharts。

## Gate 6：发布资料

- [ ] README 中英文内容、命令、截图与当前版本一致；`npm run check:readme-images` 通过。
- [ ] 同一提交的 macOS、Linux、Windows CI 全部成功后再打稳定版本标签。
- [ ] README 不包含临时占位说明或维护者本机路径。
- [ ] package metadata 已填写真实仓库信息。
- [ ] 版本号、变更记录和 license 一致。
- [ ] 发布前已人工检查 Git diff、包清单和提交内容。

## 发布判定

- `Blocked`：存在核心流程错误、数据口径错误、隐私泄漏或包无法启动。
- `Recheck required`：修复已提交，但完整 Gate 尚未重新执行。
- `Conditionally ready`：无 P0，剩余问题已经明确记录并获得发布决策。
- `Ready for release`：所有发布 Gate 有可复现证据，且无未关闭 P0/P1。
